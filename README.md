# Диспетчер заявок службы поддержки

Большое практическое задание: бинарное дерево поиска, двоичная куча
и сортировка кучей для обработки заявок службы поддержки.

## Возможности

- Хранение заявок в бинарном дереве поиска по ключу `id`.
- Вставка, поиск и удаление узлов (лист, один потомок, два потомка, корень).
- Четыре обхода дерева: прямой, симметричный, обратный, уровневый.
- Анализ дерева: количество узлов, листьев, высота, глубина, минимум,
  максимум, проверка свойств бинарного дерева поиска.
- Построение максимальной двоичной кучи по ключу `(priority, id)`.
- Сортировка кучей in-place.

## Модель данных

Заявка `Request` содержит:

- `id: int` — уникальный числовой идентификатор (ключ BST);
- `title: str` — краткое наименование;
- `priority: int` — приоритет, чем больше значение, тем срочнее заявка.

Ключ сравнения заявок в куче: `(priority, id)`.

## Этапы работы

1. Построение бинарного дерева поиска по 15 исходным заявкам.
2. Четыре обхода дерева: прямой, симметричный, обратный, уровневый.
3. Поиск и анализ характеристик дерева.
4. Вставка и удаление узлов, проверка свойств BST.
5. Построение максимальной двоичной кучи.
6. Сортировка кучей.

## Примечания

- Все структуры данных (дерево, куча) реализованы самостоятельно.
- Из стандартной библиотеки используются только `dataclass` и `deque`.
- Сортировка кучей выполняется in-place, без создания второго массива.
- Удаление узла с двумя потомками выполняется через симметричного
  преемника (минимальный узел в правом поддереве).
